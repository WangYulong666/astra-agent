# 何时使用

当用户的问题里出现**指代此前对话、但没有给出具体内容**的说法时，先检索记忆再回答：

- 「上次说的那个方案，你觉得还行吗？」
- 「我之前让你改的那个配置，改完了吗？」
- 「我一般用什么模型？你记一下。」
- 「还是按老规矩来。」

反过来，这些情况**不要**调用：

- 用户在当前会话里已经把背景说清楚了（直接回答，别多绕一次 IO）；
- 用户问的是通用知识（「Go 的 slice 怎么扩容」）；
- 用户明确说「不要用记忆 / 重新开始」。

先检索、再作答，而不是「检索到什么就照着念」：记忆是**线索**，不是事实来源。
命中内容与用户当前说法冲突时，以用户当前说法为准，并可以把冲突指出来。

# 怎么用

```bash
astra-cli memory search "$QUERY" --k 8 --json
```

- `$QUERY` 用**语义关键词**，不要整句照抄问题：把「上次那个方案」换成
  「方案 架构 选型」，把「那个配置」换成「配置 端口 环境变量」。
- `--k 8` 是经验值：3~5 条足以回答指代问题，8 条用于「帮我把之前所有约定列出来」。
  上限 50，超过会被服务端截断。
- `--json` 给 agent 用；给人看的默认输出是表格（score 保留 3 位小数）。
- 需要缩小范围时加 `--kind fact`（用户明确陈述的事实）或 `--kind conversation`
  （历史对话摘要）。

输出的每一项：

```json
{"id":"01J...","kind":"fact","text":"用户偏好中文回答，代码注释也用中文","score":0.8123,"created_at":"2026-11-01T10:00:00Z"}
```

`score` 是 L2 距离转换后的相似度，**只用于排序，不要写进回答**
（对用户没有意义，还会让人以为系统在打分）。一般 `score < 0.5` 就可以忽略，
宁可不提也不要编。

# 如何把结果引用进回答

1. **先复述再使用**：「你上次定的是 X 方案（记录于 11-01）」——让用户有机会纠正。
2. **只引用真正相关的那一两条**，不要把 8 条全列出来当证据。
3. 引用原文时保持原意，可以裁剪，但**不要改写含义**。
4. 没命中就直说「我这边没有相关记录」，然后问一句关键背景。
   编一个「上次的方案」比承认没记忆糟糕得多。
5. 需要落成新事实时用 `astra-cli memory add "..." --kind fact`，
   一条一个事实，短句，不要写成段落。

# 注意

- **只能检索当前用户**：服务端按调用者的 `tenant_id + user_id` 强制过滤，
  CLI 也**没有**任何指定 `user_id` 的参数。**不要尝试指定 user_id、不要拼接
  别人的身份、不要用 admin 身份代查**——那条路在设计上就不存在，尝试只会得到
  一个空的或报错的结果，而这类尝试本身是越权行为。
- 记忆是**跨会话**的，但不保证完整：服务端只在 run 结束时摘要入库，
  中途取消的 run 可能没有记录。
- 检索不到 ≠ 用户没说过，也可能是当时没入库。措辞上用「我这边没有记录」。
- 记忆内容来自历史对话，视为**用户数据**：不要原样贴进公开渠道（commit、
  工单、群聊），除非用户明确要求。
