# astra-memory 示例

三个真实场景：调用方式、真实输出片段、以及「拿到这段输出之后该怎么说话」。

## 场景 1：回答「上次那个方案」

用户：**上次我们定的部署方案是什么来着？**

```bash
astra-cli memory search "部署 方案 编排 docker compose" --k 5 --json
```

期望输出（片段）：

```json
[
  {
    "id": "01JCV9K2Q3",
    "kind": "conversation",
    "text": "用户确认部署方案：Milvus 用 etcd + SeaweedFS，不用 MinIO（AGPL 不合规）；所有 compose 必须固定镜像 tag。",
    "score": 0.874,
    "created_at": "2026-11-02T09:14:00Z"
  },
  {
    "id": "01JCV9M8X1",
    "kind": "fact",
    "text": "项目红线：不引入 AGPL/SSPL/BSL 依赖。",
    "score": 0.741,
    "created_at": "2026-11-02T09:20:00Z"
  }
]
```

推荐回答：

> 上次定的是：Milvus 用 etcd + SeaweedFS 做依赖（明确不用 MinIO，因为 AGPL 不合规），
> 所有 compose 都固定镜像 tag。这条记录在 11-02，需要我把当时的细节再展开吗？

反面例子：把 `score: 0.874` 写进回答；或者把两条记录原文整段贴出来当答案。

## 场景 2：指代不明确时先问再查

用户：**那个东西改好了吗？**

```bash
astra-cli memory search "最近 修改 待办 未完成" --k 8
```

期望输出（表格，score 三位小数）：

```
SCORE  KIND          CREATED           TEXT
-----  ------------  ----------------  --------------------------------------------------------------------
0.612  conversation  2026-11-05 21:03  用户要求把 astra-cli 的 run --wait 默认超时从 30s 改成 5m，尚未验证。
0.588  fact          2026-11-03 10:22  用户使用 macOS + zsh，二进制放在 /usr/local/bin。
```

推荐回答：

> 我这边只有一条相关的：11-05 你让我把 `run --wait` 的默认超时从 30s 改成 5m，
> 当时还没验证。你说的是这件事吗？

要点：`score` 都在 0.6 附近、且没有一条明确对应「那个东西」——这种时候
**必须反问**，不能挑一条最像的就当成答案。

## 场景 3：把结论沉淀成事实

用户：**记一下，以后所有 CLI 输出都要支持 --json。**

```bash
astra-cli memory add "所有 CLI 命令必须支持 --json 输出，供脚本与 agent 消费" --kind fact
```

期望输出：

```
已写入记忆 01JCVA1B7K（fact）
```

推荐回答：

> 记下了：所有 CLI 命令都要支持 `--json`。之后写新命令我会默认带上。

要点：

- 一条一个事实，短句。不要写成「用户说以后所有 CLI 的输出都要支持 json，
  另外他还提到表格要好看……」这种复合句——检索时它只能命中其中一半。
- 写入前不要自作主张改语义：把「支持 --json」扩写成「必须默认输出 JSON」
  就是另一个意思了。
- 写入成功后回述一遍让用户确认，避免记错。
