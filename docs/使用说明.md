# Astra 使用说明

> 版本 0.2.0 · macOS arm64 · 更新于 2026-10-30

## 这是什么

Astra 是一个 **Agent 工作台**：你下指令，agent 在独立沙箱里干活（写文件、跑命令），
关键操作会停下来等你审批，产物随时查看。

## 安装

1. 拿到 `Astra-0.2.0.dmg`，双击打开
2. 把 **Astra** 拖进 Applications
3. 启动台打开 Astra

> 首次打开如果提示「无法验证开发者」，右键 → 打开，或在
> 系统设置 → 隐私与安全性 里点「仍要打开」。安装包是 ad-hoc 签名（未上 Mac App Store）。

## 首次使用（向导）

1. **创建管理员**：填邮箱和密码（至少 8 位）——这是这台 Astra 的管理员账号
2. **配模型 key**：粘贴 DeepSeek API key（`sk-…`），点「测试连接」当场验证
   - 没有 key 也可以「跳过」，agent 会以 shell 模式运行（能执行命令但不会「思考」）
   - key 只保存在本机（`~/Library/Application Support/Astra/data/llm-key.json`，0600），
     **不会进沙箱**——agent 拿到的是短期虚拟 key，env 里看不到真 key
3. 进入工作台，左侧新建会话，输入第一条指令

## 日常

- **关窗 ≠ 退出**：点红点只是收起窗口，任务继续在后台跑；Cmd+Q 或菜单「退出 Astra」才真的退出
- **审批通知**：agent 请求越界操作时会弹系统通知，回窗口点「允许/拒绝」
- **审批超时**：10 分钟无人处理会自动按「拒绝」处理，不会卡死任务
- **手机可用**：手机浏览器打开「菜单 → 关于」里显示的地址（需同一局域网），
  可以「添加到主屏幕」当 App 用

## 数据在哪

| 内容 | 位置 |
|---|---|
| 数据库、沙箱工作区、key | `~/Library/Application Support/Astra/data/` |
| 日志 | `~/Library/Logs/Astra/astra.log`（菜单里可直接打开） |
| 配置（agent 类型、自定义 key） | `~/Library/Application Support/Astra/config.json` |

卸载 = 删掉上面三个位置 + Applications 里的 Astra.app。

## config.json 可配项

```json
{
  "agent": "dsh",           // shell（默认，无需 key）/ dsh（需要 key）
  "llmKey": "sk-…",         // 也可以不写文件，走向导或环境变量 DEEPSEEK_API_KEY
  "llmBaseUrl": "https://api.deepseek.com",
  "policy": "ask",          // ask / workspace-write / allow-all / deny-all
  "dataDir": "/path/to/dir"
}
```

改完重启 App 生效（llmKey 例外：向导/设置里保存的热更立即生效）。

## 出问题了

- **打开没反应**：看 `~/Library/Logs/Astra/astra.log`，末尾通常写着原因
- **模型不回话**：设置里重新「测试连接」；401 = key 失效
- **会话卡转圈**：服务重启过的话，之前的审批会被标记失效、任务归档为失败，重发即可
- **导出诊断**：把 `astra.log` 与数据目录里的 `sandboxes/<id>/logs/` 一起发出来

## 从源码构建

```bash
make test        # Go + 前端全量测试
./scripts/build-app.sh          # 产出 dist/Astra.app + dist/Astra-<版本>.dmg
VERSION=0.3.0 ./scripts/build-app.sh
```

依赖：Go 1.22+、Node 20+、macOS 13+。构建时会自动带
`CGO_LDFLAGS="-framework UniformTypeIdentifiers"`（Command Line Tools 环境链接 Wails 必需）。

## 已知边界（诚实清单）

- 只出了 macOS arm64 包；Windows/Linux 需另行适配（Wails 支持但未打包验证）
- dsh 模式依赖 `~/.astra/agent-dsh`（本机已装）；换机器要先装 dsh 裁剪版
- 「设置」里改 key 立即生效，但改 agent 类型要重启
- 多副本部署时 run 的执行体仍钉在启动它的那个副本（审批结论跨副本已可用）
- 生产存储用 `-store postgres`（PostgreSQL 16 已真机验证：建库即可，表由服务自动迁移）
- Windows 有两个产物：服务器包（astra-server.zip，可用）与桌面壳 .exe（交叉编译产物，未在真机 Windows 上验证）

## 界面适配与显示

一套界面同时适配手机、平板、桌面，按下面几档调布局（手机上侧栏变抽屉、顶栏收成汉堡菜单）：

| 设备宽 | 表现 |
|---|---|
| ≤ 359px（iPhone SE 竖屏） | 顶栏五段一行（汉堡/品牌/标题/文件/用户），气泡 92%，路径块可横向滑动 |
| 360–479px（主流手机） | 同上，留白 12px |
| 480–767px（大屏手机/横屏） | 抽屉导航，气泡 92% |
| 768–1023px（iPad 竖屏） | 侧栏 224px 常驻，文件面板改为右侧浮层 |
| 1024–1279px | 侧栏 200px，消息列 820px |
| ≥ 1280px | 侧栏 256px，消息列 880px 居中 |
| ≥ 1680px（超宽） | 消息列 960px 居中，字号 +0.5 |

其它细节：刘海/底部安全区已留 padding；所有可点元素命中区 ≥ 44×44；长路径与代码块不硬断行、改为单行横滑并带渐隐提示；矮屏横屏（如 844×390）自动压扁输入区。

**想换主题色**：改 `web/src/theme.css` 顶部 `:root` 里的 `--accent` / `--t-accent-*`，重新 `npm run build` + 重启即可。
