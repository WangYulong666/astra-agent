## 1. 要解决什么

上一轮评估的结论是：**内核是真的，治理层是空的**。本文档补齐六块：

| 缺口 | 当前 | 目标 |
|---|---|---|
| 用户权限 | 18 条路由全裸奔 | JWT + API Key + 三角色 RBAC + 租户隔离 |
| 持久化 | 文件 JSON，单副本 | SQL（本地 SQLite / 生产 PG），同一份代码 |
| 沙箱管理 | 只有 CLI | HTTP 管理面 + 配额 + TTL 回收 + 指标 |
| 服务监控 | 只有 `/healthz` | Prometheus 指标 + 结构化日志 + 审计 |
| LLM API 管理 | key 明文进沙箱 | 网关 + 虚拟 key + 多模型路由 |
| 计费 | 无 | 网关精确记账 + 用量汇总 + 额度拦截 |
| OpenAPI | 无 | `openapi.yaml` 契约 + 运行时导出 + 校验测试 |

## 2. 六个决策

### D1 · 认证用 JWT（人）+ API Key（机器），不用 session cookie

JWT 无状态，多副本不用共享会话表；API Key 给 CLI/SDK 用。
Cookie 方案在「Web + 桌面 + 移动」三端混跑时跨域麻烦，放弃。

- JWT：HS256，`golang-jwt/v5`，默认 24h，claims = `sub`(userID) `tid`(tenantID) `role` `email`。
- 密码：bcrypt cost 12。
- API Key：`astra_sk_` + 32 字节随机 base64url；库里只存 `sha256(明文)`，明文只在创建响应里出现一次。
- 密钥来源：`ASTRA_JWT_SECRET` 环境变量；未设置时启动即生成随机值并**打醒目告警**（重启后 token 全失效，仅适合本地）。

### D2 · 存储抽象成一份 SQL，SQLite 与 PG 共用实现

本机没有 PG、也没有 brew，但生产必须 PG。方案：

- `database/sql` + 一个 `rebind()` 把 `?` 转成 `$n`（PG 需要）。
- DDL 分两份 embed（类型差异：`TEXT`/`INTEGER` vs `timestamptz`/`bigint`）。
- DSN 前缀决定驱动：`sqlite://` → `modernc.org/sqlite`（纯 Go，无 cgo）；`postgres://` → `pgx/v5/stdlib`。

**时间统一用 `time.Time` 存 UTC，读出后转 UTC**——SQLite 没有原生时间类型，靠 RFC3339 字符串往返，必须显式统一。

### D3 · 租户隔离在 API 层强制，不靠 SQL 自觉

理由：`file store` 不支持按租户查询（它只有 `ListSessions`），如果隔离逻辑写进 SQL，两种 store 行为就会不一致。

做法：所有 handler 从 `Principal` 取 `TenantID`，**绝不从请求体读**。
- `admin`/`owner`：看本租户全部会话。
- `member`：只能看 `UserID == 自己` 的会话。
- 拿单条时校验归属，不匹配回 **404 而不是 403**（403 会泄漏「该 ID 存在」）。

### D4 · 计费的唯一可信来源是 LLM 网关

实测确认：**ACP 事件流里没有 token 用量**（只有 `run_state` / `stopReason`）。
dsh 的 usage 只写在自己沙箱内的 `session_projcache` 里，路径不稳定、且属于 agent 私有实现，**不能作为计费依据**。

所以：

```
agent ──(虚拟key)──> astra 网关 ──(真key)──> DeepSeek
                        │
                        └─ 记账 ──> usage 表 ──> 计费
```

- 网关透传 OpenAI 兼容协议，流式请求自动加 `stream_options.include_usage=true` 以拿到最后一帧 usage。
- 虚拟 key = 短期 JWT（绑定 tenant/user/session，默认 2h），真 key 只存在于网关进程内存。
- `usage.source = gateway` 才参与计费；`agent` 来源仅展示。
- 顺带解决评估里的隐患：**真 key 不再进沙箱**。

### D5 · 指标用 Prometheus client，不手写文本格式

手写 exposition 格式要自己管 histogram 分桶和并发安全，不值得。用 `client_golang`。

### D6 · OpenAPI 手写单一文件，不做代码生成

`oapi-codegen` 会把现有 handler 全部重写，风险大于收益。本期：
- `docs/openapi.yaml` 手写，作为对外契约。
- 运行时 `GET /v1/openapi.json` 导出同一份内容（embed）。
- 加一个测试：解析 yaml 的 paths，与 `platform_routes.go` 里注册的路由逐一比对，**防止契约漂移**。

## 3. 数据模型

实体与接口定义在 `internal/store/admin.go`（已落地，是契约）：`Tenant` / `User` / `APIKey` / `Usage` / `AuditLog` + `AdminStore` 接口。

`Session` 增加 `TenantID` / `UserID`（`internal/store/types.go`，已落地）。

表结构由 T1 编写，要求：
- 所有 ID 为 26 字符（与现有 `newID()` 一致），用 `TEXT PRIMARY KEY`。
- 所有时间列存 UTC。
- 索引至少覆盖：`users(tenant_id, email)` 唯一、`apikeys(key_hash)` 唯一、`usage(tenant_id, created_at)`、`audit(tenant_id, created_at)`、`sessions(tenant_id, last_active_at)`。
