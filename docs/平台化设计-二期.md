# 平台化二期：网关闭环与沙箱治理

> 一期（`docs/平台化设计-认证与治理.md`）把治理层的**骨架与接口面**补齐了：
> 认证、租户、存储、指标、OpenAPI、管理后台。但有三件事只做到了「接口在、语义没兑现」，
> 二期就是把它们做成真的，并补上长期运行必须具备的生命周期治理。

## 0. 一期遗留的硬事实

翻代码与实测得到的三条，二期所有决策都基于它们：

1. **ACP 事件流里没有 token 用量**。`internal/store/types.go` 的 `Event` 只有原始 payload，
   实测 dsh 的 `run_state` 只带 `status`/`stopReason`，usage 落在 agent 自己的私有缓存里。
   ⇒ 计费数据的唯一可信来源是**网关自己记账**。
2. **dsh 走的是 Anthropic Messages 协议，不是 OpenAI 协议**。
   从 `~/.astra/agent-dsh/node_modules/@deepseek-ai/dsh-llm-deepseek/lib/index.js:345`：
   `PUBLIC_BASE_URL = "https://api.deepseek.com/anthropic"`，请求路径拼 `/v1/messages`。
   而我们的网关只按 OpenAI `/v1/chat/completions` 解析 usage。
   ⇒ 网关必须支持 Messages 的 SSE 事件格式，否则接上 dsh 也记不到账。
3. **dsh 的端点与凭据都可从环境变量覆盖**（`lib/index.js:430`）：
   - 端点：`DEEPSEEK_BASE_URL`（显式 `config.baseURL` 优先，其次该 env，最后官方根）
   - 凭据：插件 `dsh-llm-deepseek-api-key` 的 `apiKeyEnv`，默认 `DEEPSEEK_API_KEY`
   ⇒ 「真 key 不进沙箱」不必改 dsh 源码，**注入两个环境变量即可**（另留 profile patch 兜底）。

## 1. 二期范围

| 编号 | 任务 | 验收标准 |
|---|---|---|
| T1 | 网关支持 Anthropic Messages 协议 | 网关能透传 `/v1/messages`，从 `message_start` 的 `message.usage.input_tokens` 与 `message_delta` 的 `usage.output_tokens` 记账；**不向 Messages 请求注入 `stream_options`**（那是 OpenAI 专有字段） |
| T2 | 会话级虚拟 key 注入 | 会话创建时签发 2h 虚拟 key，沙箱内 `DEEPSEEK_API_KEY` 是虚拟 key，`DEEPSEEK_BASE_URL` 指向网关；沙箱内 `env` 看不到真 key |
| T3 | 沙箱生命周期治理 | 空闲/TTL 回收、孤儿清理、每租户并发沙箱配额；**只销毁沙箱资源，不删会话数据** |
| T4 | 前端测试 | vitest 跑得起来，覆盖 timeline 折叠状态机、路由解析、格式化 |
| T5 | 部署清单可执行化 | 无 `PLACEHOLDER`；PG 与迁移 Job 齐备；结构自检脚本可跑 |

不在二期：Wails 桌面端、移动端、CubeSandbox 真机验证、自研 dsh 逐条审批插件。

## 2. 决策

### D6 网关按「协议族」分流，不做格式转换

不改写请求体做 OpenAI ↔ Messages 互转。理由是转换要处理 tool_use/tool_result/thinking
等大量结构差异，一旦转换有损，模型会表现为「变笨」而无报错，排查成本极高。

做法：按请求路径判定协议族（`/messages` → Messages，`/chat/completions` → OpenAI），
**原样透传**，只在两处介入：
- 认证头：把虚拟 key 换成真 key（Messages 用 `x-api-key` 与 `Authorization` 双写，
  因为不同网关实现认的字段不同，双写无副作用）
- usage 记账：按各自的事件格式解析

上游地址天然对上：dsh 的 baseURL 设成 `{网关}/v1/llm/anthropic`，它拼出
`/v1/llm/anthropic/v1/messages`，剥掉 `/v1/llm` 前缀后正好是
`https://api.deepseek.com/anthropic/v1/messages`。

### D7 虚拟 key 只走环境变量，**不**在 patch 里写 baseURL

（原方案是「环境变量 + patch 兜底」双保险，实施中被源码与实测推翻，故改为此条。）

注入两个环境变量：
- `DEEPSEEK_API_KEY` → 虚拟 key（JWT 形态，2h）
- `DEEPSEEK_BASE_URL` → `{publicURL}/v1/llm/anthropic`

链路生效的依据（`~/.astra/agent-dsh/node_modules/@deepseek-ai/` 下）：
`dsh-llm-deepseek/lib/index.js:430` 的解析顺序是
`config.baseURL ?? environment.get("DEEPSEEK_BASE_URL") ?? 官方根`；
`dsh-launch-environment/lib/index.js` 的快照默认就是 `process.env`。

**为什么不能写 patch**：`config.baseURL` 的优先级**高于**环境变量。一旦在
`astra-trim.yml` 里写死 baseURL，就会永久遮蔽 `DEEPSEEK_BASE_URL`，
本机与集群的地址必然有一条失效，而且失效方式是「明明改了环境变量却没效果」。

原方案还有一个方向性错误：那份 patch 是按内容哈希落盘、全进程共享的，
而虚拟 key 是 per-session 的——写进去就得为每个会话生成一份新 patch 文件，
落盘量随会话数线性增长且没有回收路径。

### D8 网关地址是显式配置项，不猜

`-llm-public-url` 传给 agent 的是**agent 视角**可达的地址，与控制面自己监听地址不是一回事
（本机 `127.0.0.1:7788` 能用，k8s 里必须是 service DNS 或对外域名）。
不配则该能力关闭，绝不回落到「猜一个」。

### D9 沙箱回收与配额都是「有主判断」，不是无脑删

回收前三件事必须依次成立：沙箱无对应会话（孤儿）→ 或会话已非 active → 或超出 TTL/空闲阈值。
`Destroy` 只销毁资源，会话记录与事件保留——这与一期「强杀沙箱不动数据」的语义一致。

配额是**准入控制**（创建前拒绝），不是事后清理。清理只能兜底，不能替代准入。

### D10 前端测试只测纯逻辑，不引 DOM 测试栈

`timeline.ts` 的事件折叠是纯函数（事件数组 → 块数组），`router.ts` 是纯解析，`format.ts` 是纯格式化。
这三块正是最容易回归的（一期工具卡片空白、审批卡片无标题都是这里的问题）。
引 `@testing-library/react` 需要 jsdom 与大量配置，收益不抵成本，不引。

## 5. 验证要求

每条都要有可复现的证据，不接受「应该能跑」：

- T1：假上游返回 Messages 格式 SSE，断言 usage 被解析（单测）；真 dsh 跑一次，`/metrics` 的
  `astra_llm_tokens_total` 增长、`usage` 表有记录
- T2：沙箱内执行 `env | grep DEEPSEEK`，`DEEPSEEK_API_KEY` 必须是 JWT 形态（三段 base64url，
  形如 `x.y.z`，没有 `sk-` 前缀），`DEEPSEEK_BASE_URL` 指向网关；用同一个虚拟 key 直接调网关能拿到模型回复
- T3：造一个孤儿沙箱 + 一个超时沙箱，`Sweep` 后都被销毁，而有主且在阈值内的不动
- T4：`npm test` 通过，故意改坏 timeline 的一个分支时测试必须红
- T5：`tools/check-deploy.sh` 通过；`grep -r PLACEHOLDER deploy/` 为空

### 过程中被修正的两个判断

1. **D7 的 patch 兜底被推翻**（见上）。这是「先写设计、后被源码纠正」的正常结果，
   记在这里是为了不再有人把 baseURL 往 patch 里加。
2. **`migrate-job.yaml` 原本用 psql 跑一份 DDL 副本**（因为当时没有迁移入口）。
   本轮补上 `-migrate-only` 后改为调用二进制本身——DDL 回到单一事实来源，
   否则每次加迁移版本都要同步两处，漏一次就是「Job 成功但表少一张」。
