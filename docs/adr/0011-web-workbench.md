# ADR-0011：Web 工作台的形态（手写样式 + 内嵌产物 + 单人时间线）

- 状态：已采纳
- 日期：2026-10-29
- 关联：ADR-0006（不引开源后台脚手架）、ADR-0009（控制面形状）

## 背景

控制面已经有完整的 REST + SSE（会话、run、事件流、审批、文件），但只有一张
333 行的内嵌演示页——它能证明协议通，不能算产品：

- 事件是裸 JSON 列表，看不出「一段回答中间调了个工具」
- 没有撤销/停止、没有审批按钮、刷新页面后要重新点一遍
- 没法看 agent 到底往工作区写了什么

需要把这些能力做成一个能真的用起来的界面。

## 决策

### 1. React + Vite，不引 UI 组件库

界面结构是固定的三栏（会话 / 对话 / 文件），信息密度要求高，交互只有
「点击展开」「点击审批」两类。引 Ant Design / MUI 会带进它们的设计语言与
主题体系，反而要花更多代码去对抗默认样式。

代价：没有现成的表格、虚拟列表、弹层。当前用不到；真需要时按件引入，
不要一开始就把整个库背进来。

### 2. 不引 markdown 库，自己写 120 行渲染器

agent 的输出里 90% 是代码块 / 标题 / 列表 / 行内代码 / 粗体 / 链接。
`react-markdown` 带 40 多个传递依赖，而自己写的好处是**不渲染 HTML**——
天然没有 XSS 面，也就不需要在「用户让 agent 输出一段 HTML」时做消毒。

超出支持范围的语法按纯文本渲染，不会误导人；这比「支持所有 CommonMark 但可被注入」
更合适。

### 3. 构建产物入库，`go:embed` 打进二进制

`internal/api/web/dist` 提交进仓库，被 `//go:embed all:web/dist` 嵌入。

理由：`go build` 在编译期就要读到这个目录。不入库的话，「克隆下来 make serve」
必须先装 node 并联网装依赖——这会让「一条命令跑起来」这个目标失守。
产物 ~200KB（gzip 后 ~60KB），换来的是发布只有一个二进制。

代价：改前端要记得 `make web` 再 `make serve`，否则二进制里还是旧界面。
开发时用 `make web-dev`（vite 热更新 + 代理到 7788），不受这个影响。

### 4. 时间线在客户端折叠，服务端不存「视图」

服务端存的是协议级事件（`message_delta` / `tool_call_start` / `approval_req` …），
前端用 `buildBlocks` 折叠成「消息 / 思考 / 工具卡片 / 审批」四类块。

为什么不在服务端折叠：折叠规则会随 UI 变化（比如以后要把同一次工具调用的
输入输出合成一张 diff 卡片），把它固化进存储等于把视图耦合进数据。
原始事件是唯一事实来源，刷新页面能原样重建——这正是 ADR-0009 里
「事件先落库再推送」的回报。

### 5. 首屏走 JSON 历史，SSE 只负责「从此刻起」

`GET /v1/runs/{id}/history` 返回事件数组，`GET /v1/runs/{id}/events` 是 SSE。
分成两个接口而不是让前端解析 SSE 文本：SSE 的语义是「回放完历史再推实时，
终态即关连接」，用它做首屏要额外处理「连接建立前的历史」，两边都变复杂。

客户端仍然保留 `after_seq` 去重：历史与流可能重叠，按 seq 幂等合并。

### 6. 恢复语义交给后端，前端只做重连

- 断线：`EventSource` 自动重连；服务端在缓冲满时发 `event: overflow` 主动断开，
  客户端带 `after_seq` 续传
- 刷新：重新拉历史 + 对非终态 run 重挂 SSE
- 重启：后端 `RecoverInterrupted` 把中断的 run 归档成失败，前端照常显示

前端不做任何本地持久化——多端一致性的前提是「状态只有一份」，
浏览器存一份必然漂移。

## 后果

好：

- 一个二进制 = 完整产品。`make serve` 之后浏览器打开就是工作台。
- 审批、停止、文件浏览都在界面上完成，不用 curl。
- 视图规则改动只影响前端，历史数据不动。

坏 / 需要接受：

- 前端没有虚拟列表：一个会话几百轮之后 DOM 会变重。当前按「一次会话几十轮」设计，
  真超了再加窗口化。
- 没有路由（`/` 一个页面），分享链接只能到「最近会话」，不能指向具体会话。
- 不引 UI 库的代价是表单、下拉、toast 都要自己写；目前只写了 toast。

## 被否掉的方案

| 方案 | 为什么不用 |
|---|---|
| 继续用内嵌单页 HTML（无构建） | 状态管理、折叠逻辑、审批交互会迅速膨胀到不可维护 |
| 引 Vben Admin / Ant Design Pro 作为壳 | ADR-0006 已否：会带进第二套 RBAC 与审计 |
| Next.js / SSR | 控制面本身就是 API，SSR 只增加一层部署面；也不需要 SEO |
| 服务端渲染好 HTML 片段推到前端 | 等于把视图协议塞进事件流，历史数据会绑定某一版 UI |
| 前端直连沙箱的 acp-proxy | 违反 ADR-0002：一条 ACP 连接只能有一个持有者，多端必须经控制面 |
